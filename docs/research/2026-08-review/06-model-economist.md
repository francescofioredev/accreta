# Model routing and what each phase actually costs

> One of six independent reviews, August 2026. Each reviewer worked from a single
> disciplinary lens with no sight of the others' work; an adversarial verifier then
> checked every citation and every `file:line` and rejected what did not survive.
> **Read `00-register.md` for what was confirmed** — this report is the raw finding,
> before verification.
>
> **Owns:** Q8 (cost and model choice per phase)
> **Agent:** `.claude/agents/accreta-model-economist.md`
>
> Evidence grades: **MEASURED** (ran it, with numbers and command) ·
> **CITED** (a source with the specific result relied on) ·
> **REASONED** (an argument from the code, the weakest grade).

Two confirmations before the findings: changedSince returns FILE PATHS ONLY (no line-level diff), and the MCP server exposes NO way to read source text - the agent must read sources through its own file tools. Both matter for the token-flow analysis.

## F-ME-01: Lint detection costs zero LLM tokens; the entire cost is in fixing, and the five finding kinds differ by ~1000x
- Severity: medium
- Evidence: REASONED - packages/core/src/query/lint.ts:36-110 is pure SQL over the index: two queries for broken_links and dangling links, one over pages, plus a Set membership test against config.pageTypes. No adapter call, no source read, no model. Fix-cost profiles below are REASONED from what each finding requires the fixer to look at, NOT measured.
- Where: packages/core/src/query/lint.ts:36-110; packages/mcp-server/src/tools.ts (lintTool)
- Failure scenario: A user reads "linting" as an agent phase and budgets model spend for it, or a reviewer proposes "use a cheap model for lint" - a recommendation about a phase THAT RUNS NO MODEL AT ALL. The real decision is per finding kind, and one kind (missing-provenance) costs the same as ingest.
  Cost per finding kind. "Source re-read" is the load-bearing column, because reading an RFC-sized source is 20k-125k input tokens while everything else is kilobytes.
  | Finding kind | What the fix requires | Source re-read? | Cheapest defensible model |
  | unknown-page-type | change one frontmatter word to a configured type | No | DETERMINISTIC SCRIPT; no model needed |
  | unverified-page | add last_verified_revision | YES - MANDATORY | Ingest-tier. See F-ME-02 |
  | dangling-link | find where the page went, or delete the link | No | Small model + search_pages |
  | broken-link | resolve an unresolvable target | No | Small model + search_pages |
  | missing-provenance | establish what the page's authoritative definition actually is | YES | Same tier as ingest |
- Falsifiable proposal: Document in README.md or the CLI's lint help that DETECTION IS DETERMINISTIC AND FREE, and split the fix guidance by kind. Disproof: if a per-kind fix study shows unverified-page and missing-provenance are fixed correctly at the same rate by a small model as by a frontier one, the split is wrong and one recommendation suffices.
- Cost to verify: 3-4h to instrument fixes per kind on a populated KB. Gated on the ingest experiment, since accreta-atlas/kb/knowledge/ is empty.
- Confidence: high for the zero-token claim (the code is deterministic); MEDIUM for the per-kind tiering, which is REASONED not measured.

## F-ME-02: unverified-page is not the mechanical fix it appears to be - the cheap fix is the one the constitution names as maximally damaging
- Severity: CRITICAL
- Evidence: REASONED - packages/core/src/query/lint.ts:103-108 emits the finding purely from last_verified_revision IS NULL. updateVerifiedRevisionTool writes the field after a dry-run token handshake AND NEVER READS THE SOURCE. templates/constitution/base.md: "Bumping last_verified_revision without re-reading converts a detectable problem into an undetectable one, and is the single most damaging thing you can do here."
- Where: packages/core/src/query/lint.ts:103-108; packages/mcp-server/src/tools.ts (updateVerifiedRevisionTool); templates/constitution/base.md
- Failure scenario: An agent is told "fix the lint findings". unverified-page LOOKS LIKE A MISSING FIELD, so it calls update_verified_revision with the source's current revision, gets a token, echoes it, and writes. Lint goes green, drift reports current, and THE PAGE'S CLAIMS WERE NEVER CHECKED AGAINST ANYTHING. The system now asserts verification it does not have - a silent violation of provenance and drift detection at once - AND IT IS CHEAPER THAN DOING IT CORRECTLY, SO ANY COST-DRIVEN MODEL CHOICE SELECTS FOR IT.
- Falsifiable proposal: Make the write tool require evidence of a read: have update_verified_revision take a checked_paths argument and REFUSE a revision when the page's canonical_source path is absent from it - a shape check, not proof of reading, but it makes the empty call impossible to issue by reflex. Disproof: if transcripts of small-model unverified-page fixes show source reads already precede every bump without the gate, the gate adds friction for nothing.
- Cost to verify: 2h to instrument (count source reads preceding each update_verified_revision call in transcripts). Needs the ingest experiment's transcripts to exist.
- Confidence: high that the gap exists in code; medium that models actually take the shortcut - that is the thing to measure.

## F-ME-03: accreta never checks that a citation points at a line range that exists - a model can fabricate line numbers and pass lint
- Severity: CRITICAL
- Evidence: REASONED - grep -rn "canonical_source" packages/ --include="*.ts" returns five non-test sites: the lint null-check (lint.ts:96), an index write (build.ts:188), two query reads (page.ts:21,33), one CLI print (commands.ts:318). NONE PARSES IT. grep -rn '#L' packages/*/src finds line-range handling ONLY in formatCitation (packages/core/src/source/adapter.ts:64-88), which RENDERS a range into a string and never reads one back. Footnote citations in page bodies are stored as opaque body text in pages_fts; nothing parses them at all.
- Where: packages/core/src/query/lint.ts:96-101; packages/core/src/source/adapter.ts:64-88
- Failure scenario: A model ingests RFC 9110 and writes canonical_source: "rfc-http:rfc9110.txt#L4200-L4260" for a page on caching semantics. The file has 10,785 lines, so THE RANGE EXISTS BUT THE CONTENT IS ABOUT SOMETHING ELSE - or the model writes #L99999-L99999, past the end. accreta lint reports ZERO findings for that page, accreta drift reports it CURRENT, and find_canonical returns it as THE AUTHORITATIVE ANSWER. Every downstream consumer treats a fabricated pointer as verified provenance. This is the exact failure the project's FIRST STATED PROPERTY is supposed to prevent.
- Falsifiable proposal: Add two deterministic checks to lint, both cheap and both requiring only SourceAdapter.read (ALREADY ON THE INTERFACE, so no adapter branching): (a) the cited path resolves inside the named source; (b) the cited line range lies within that file's line count. Emit as new finding kinds (citation-path-missing, citation-range-out-of-bounds). Disproof: run the checks over a real ingested KB and find zero violations across several models - then fabrication is not an empirical problem and the checks are ceremony. My prediction is the opposite. NOTE (a) AND (b) CANNOT CATCH A PLAUSIBLE BUT WRONG RANGE; that is metric (c) and needs judgement.
- Cost to verify: 4-6h to implement both checks plus tests. NEEDS NOTHING THAT DOES NOT EXIST - read() is already on SourceAdapter.
- Confidence: high. The absence is established by reading every reference to the field.
- CREDIT: this gap sits next to a piece of design that is genuinely careful. updateVerifiedRevisionTool is gated twice - an env var and a dry-run token derived from (path, revision, currentValue) - so a model cannot skip to writing and cannot replay a token onto a different edit. A reviewer looking for provenance weaknesses would be tempted to attack that tool; IT HOLDS. The weakness is one layer up, in what is never checked at all.

## F-ME-04: The token bill is dominated by source text, and the MCP server offers no way to read it - so the phase costs are set outside accreta
- Severity: high
- Evidence: MEASURED and REASONED. Measured on the vendored corpus (wc -c over accreta-atlas/kb/corpus/rfc/*.txt, 2026-08-10): 1,691,783 bytes total. At bytes/4: RFC 9110 ~125.7k tokens, 8446 ~84.4k, 7231 ~58.8k, 7540 ~52.4k, 6455 ~40.5k, 9114 ~38.8k, 9111 ~21.1k, 2119 ~1.2k - ~423k ESTIMATED TOKENS FOR THE WHOLE CORPUS. Constitution: accreta-atlas/kb/AGENTS.md is 11,093 bytes ~ 2.8k tokens, loaded per session. Measured MCP responses (bun run bench/mcp-budget.ts --sizes=10,100,1000, darwin arm64, bun 1.3.13): at 1,000 pages lint 159.2KB / ~40.8k est tokens / 20.4% of a 200k window; find_consumers on a hub 157.1KB / ~40.2k / 20.1%; get_page flat 29.8KB / ~7.6k; search bounded at 6.5KB. REASONED: grep for adapter.read across packages/mcp-server/src returns NOTHING - no tool exposes source text.
- Where: bench/mcp-budget.ts; packages/mcp-server/src/tools.ts; accreta-atlas/kb/corpus/rfc/
- Failure scenario: Two distinct ones. (i) The DOMINANT per-phase cost is reading sources, which happens ENTIRELY THROUGH THE CALLING AGENT'S OWN FILE TOOLS - accreta cannot cache it, bound it, or even see it. A user optimising "accreta's model cost" by tuning MCP usage is optimising the SMALL TERM. (ii) At 1,000 pages an agent calls lint_knowledge_base to fix findings and spends a fifth of its window on the answer; the harness extrapolation puts 10,000 pages at ~408k tokens - TWICE a 200k window, so the response cannot be received at all. Paid twice: once in context, once in money at the input rate.
  Priced against verified rates (Anthropic pricing page, fetched 2026-08-10 - Opus 5 $5/MTok in, $25/MTok out; Sonnet 5 $2/$10 introductory through 2026-08-31, $3/$15 after; Haiku 4.5 $1/$5; cache read 0.1x base, 5m cache write 1.25x, 1h write 2x; Batch API 50% off both directions):
  | Item | Est tokens | Opus 5 | Sonnet 5 (intro) | Haiku 4.5 |
  | Read RFC 9110 once, uncached | ~125.7k in | $0.63 | $0.25 | $0.13 |
  | Same, as a cache read | ~125.7k in | $0.06 | $0.03 | $0.01 |
  | Whole 8-RFC corpus, uncached | ~423k in | $2.12 | $0.85 | $0.42 |
  | Constitution, per session | ~2.8k in | $0.014 | $0.006 | $0.003 |
  | One lint at 1,000 pages | ~40.8k in | $0.20 | $0.08 | $0.04 |
  TWO THINGS FOLLOW. First, whole-corpus INPUT cost is small in absolute terms even at Opus rates - the interesting variable is OUTPUT tokens and REWORK, not input. Second, CACHING IS THE SINGLE LARGEST AVAILABLE LEVER on the input side (10x), and it only pays if the corpus prefix is stable across calls; a frozen corpus like the RFC set is the best possible case for it.
- Falsifiable proposal: Paginate the four unbounded tools with the same limit/offset shape search_pages already uses, and document plainly that SOURCE READING IS THE CALLER'S COST AND ITS OWN MODEL'S CONCERN. Disproof: if real ingest transcripts show lint is never called on a KB above a few hundred pages, the pagination is speculative engineering for a scale nobody reaches.
- Cost to verify: benchmark exists and reruns in ~1 min. Confirming the SHAPE of real spend needs transcripts in accreta-atlas/sessions/ - THE DIRECTORY IS NAMED IN THE README'S LAYOUT BUT DOES NOT EXIST YET ON DISK.
- Confidence: high for the measured numbers; medium for the claim that source reading dominates in practice, since no real ingest transcript exists to check the ratio against.

## F-ME-05: Model routing is not accreta's concern, and the honest deliverable is a documented cost profile per phase
- Severity: medium
- Evidence: REASONED - packages/core/src/config.ts parses knowledge_base, page_types, link_fields, provenance.format and NOTHING MODEL-RELATED; grep -rn "ACCRETA_" finds only ACCRETA_ALLOW_WRITES. The MCP server is stdio-only and HOLDS NO MODEL HANDLE; the model lives entirely in the client.
- Where: design-level; packages/core/src/config.ts, packages/mcp-server/src/server.ts
- Failure scenario: accreta grows a models: config block to "route ingest to Opus and drift to Haiku". IT CANNOT: it never calls a model, so the field would be ADVISORY TEXT THE CLIENT IS FREE TO IGNORE - configuration that looks like control and is not. Worse, it would create a SECOND PLACE WHERE PHASE SEMANTICS LIVE, competing with the constitution, which is the artifact that actually reaches the model.
- Falsifiable proposal: DO NOT ADD MODEL CONFIGURATION. Instead put a short cost-profile table in templates/constitution/base.md, WHERE IT REACHES THE AGENT, stating for each phase what enters context and which phases require a source re-read - the property that actually drives cost and correctness. Disproof: if a user demonstrates a workflow where accreta itself must invoke a model (for example a future accreta ingest that DRIVES the loop rather than being driven by it), routing becomes accreta's problem and this finding is wrong. NOTE docs/architecture.md names an ingest CLI command THAT DOES NOT EXIST - if that is a real intention rather than staleness, this conclusion needs revisiting.
- Cost to verify: 0h to establish current state; the disproof depends on a roadmap decision, not a measurement.
- Confidence: high on the architectural fact, medium on the recommendation, since it rests on ingest never becoming a real command.

## Experiment card: citation validity per dollar, over the frozen RFC corpus
- Question: For a single ingest of a fixed corpus, how does model choice change the number of VALID citations produced per dollar?
- Hypothesis: Frontier and mid-tier models produce SIMILAR PAGE COUNTS but differ materially in citation validity - specifically in (b) line-range existence and (c) support. If so, $/page RANKS MODELS DIFFERENTLY FROM $/valid-citation, and $/page is the misleading metric.
- Method:
  1. CORPUS, FROZEN AND IDENTICAL. accreta-atlas at a pinned commit; kb/knowledge/ starts EMPTY for every arm. Three sources over the 8 vendored RFCs. NEVER EDIT A CORPUS FILE - per kb/corpus/rfc/PROVENANCE.md, one byte advances the revision and makes every page stale at once.
  2. ARMS. One per model, verified 2026-08-10 against the Anthropic pricing page: claude-opus-5 ($5/$25), claude-sonnet-5 ($2/$10 intro through 2026-08-31; RE-VERIFY IF RUN AFTER THAT DATE), claude-haiku-4-5 ($1/$5). Any non-Anthropic or open-weight arm must have its price fetched from that provider's own page on the run date, and FOR OPEN WEIGHTS THE FIGURE IS A HOSTING PROVIDER'S PRICE, NOT THE MODEL'S - label it as such. Run each arm THREE TIMES (n=1 per arm cannot separate model from sampling variance).
  3. HELD CONSTANT. Identical constitution, task prompt, tool surface, MCP server. Save every transcript to accreta-atlas/sessions/<model>-<run>/ - NOTE THIS DIRECTORY IS IN THE README'S LAYOUT BUT DOES NOT YET EXIST.
  4. COST CAPTURE. Sum input_tokens, cache_read_input_tokens, cache_creation_input_tokens, output_tokens per run from transcripts; PRICE EACH BUCKET AT ITS OWN RATE (cache read 0.1x, 5m write 1.25x) rather than applying the base rate to everything.
  5. SCORING (a) AND (b) - DETERMINISTIC, ~100 LINES. For every canonical_source and every footnote citation: parse source, path, #Lstart-Lend; resolve source through the configured adapter; assert the path exists; assert 1 <= start <= end <= wc -l. THIS SCRIPT DOES NOT EXIST AND ACCRETA DOES NOT DO THIS - see F-ME-03. Report path-invalid and range-invalid counts SEPARATELY.
  6. SCORING (c) - HUMAN, STRATIFIED. Sample 30 citations per run, STRATIFIED BY PAGE TYPE so contradiction pages are not swamped by concept pages. TWO RATERS, BLIND TO THE ARM, on a three-point rubric: 2 the cited lines state the claim; 1 the lines are related but do not support it as written; 0 the lines do not bear on the claim. REPORT COHEN'S KAPPA; IF KAPPA < 0.6 THE RUBRIC IS BROKEN AND THE NUMBERS DO NOT MEAN ANYTHING YET. An LLM judge is permissible ONLY alongside these human labels, reporting agreement with them - an unchecked judge shares the generator's failure modes, and on this task the specific shared bias is JUDGING PLAUSIBILITY RATHER THAN CHECKING THE LINE RANGE.
- Metric: $/VALID-CITATION, valid = (a) AND (b) AND (c)=2. Report $/page beside it. $/valid-citation is the honest one because A PAGE IS NOT THE UNIT OF VALUE HERE - A CITED CLAIM IS. A model that writes twice as many pages at half the citation validity has produced the same amount of knowledge and more liability, and $/page scores it as twice as good.
- Falsification criterion: The hypothesis FAILS if, across 3 runs per arm, the arms' (a)AND(b) validity rates fall within OVERLAPPING 95% binomial confidence intervals AND the $/valid-citation ordering matches the $/page ordering. Then model choice does not affect provenance quality on this corpus and the cheapest arm wins outright.
- Cost: Input is bounded and small - ~423k est tokens for the full corpus, so even reading everything once per run costs ~$2.12 (Opus 5), ~$0.85 (Sonnet 5 intro), ~$0.42 (Haiku 4.5). OUTPUT AND REWORK DOMINATE AND CANNOT BE ESTIMATED BEFORE THE FIRST RUN - RUN ONE SONNET ARM FIRST AND USE ITS ACTUAL usage TO BUDGET THE REST, rather than trusting my input-side arithmetic. Human scoring ~2h per run for 30 citations x 2 raters, which is THE REAL COST and the reason (c) is sampled rather than exhaustive. Engineering ~6h.
- Not measured: Anything about drift (separate card). Anything about a corpus that is not 8 IETF RFCs. Cost of MAINTAINING a KB over time, since this measures one cold ingest.

## Experiment card: drift re-verification as binary classification, with the asymmetry priced in
- Question: When a cited region changes, can a model correctly decide whether the page's claim still holds - and does that depend on model tier?
- Hypothesis: "A small model suffices for drift" is A HYPOTHESIS, NOT AN ASSUMPTION. Plausible because the task is binary classification over a narrow localised context; plausible is not measured, and the asymmetry means a wrong answer in one direction is far more expensive.
- Method: (1) Start from a KB produced by the ingest experiment, so pages have real citations. (2) Build the gold set BY COPYING THE CORPUS TO A SCRATCH SOURCE, NEVER BY EDITING kb/corpus/rfc/. For 40 cited regions, two perturbation classes, 20 each: INVALIDATING (change a normative keyword per RFC 2119 - MUST->SHOULD; change a numeric value; reverse a condition) and COSMETIC (reflow whitespace; fix a typo in a non-load-bearing word; renumber an unrelated adjacent section). Ground truth is the perturbation class, assigned at construction and recorded before any model sees it. (3) Present each perturbed region with the page's claim; ask for a verdict. Same 3-run repetition. (4) NOTE THE MECHANICAL CONSTRAINT THAT SHAPES THIS TASK: changedSince returns FILE PATHS ONLY (packages/adapters/git/src/index.ts:106-109), and drift.ts never cross-references changedPaths against canonical_source. So the model is handed "this file changed", not "these lines changed" - THE LOCALISATION THE MODEL MUST DO ITSELF IS PART OF WHAT IS BEING MEASURED.
- Metric: THE FULL 2x2 CONFUSION MATRIX PER ARM. Never a single accuracy figure, and NEVER A SINGLE F-SCORE: F1 averages away exactly the asymmetry that decides the threshold.
- Threshold choice, stated explicitly: The constitution's asymmetry is that a false "still valid" is SILENT DECAY - the page is wrong and nothing will ever flag it - while a false "no longer valid" only wastes human attention on a re-read. So the threshold MINIMISES FALSE "STILL VALID", accepting false "no longer valid" freely. Concretely: an arm is acceptable only if its false-"still-valid" rate is below 5%; its false-"no-longer-valid" rate is a cost line, NOT A GATE.
- Falsification criterion: "A small model suffices" is refuted if claude-haiku-4-5's false-"still-valid" rate exceeds 5%, or if its 95% CI on that rate overlaps 5%. n=20 per class is small - A 1/20 ERROR IS A POINT ESTIMATE OF 5% WITH A 95% CI OF ROUGHLY 0.1%-25%, SO THIS DESIGN CANNOT RESOLVE A 5% THRESHOLD AND NEEDS ~200 PERTURBATIONS PER CLASS TO DO SO. State that honestly rather than reporting the underpowered result.
- Cost: Small in tokens - each judgement is a narrow context. Construction of the gold set is the real cost: ~4h for 40 perturbations, ~20h for the 200/class the threshold test actually requires.
- Not measured: Whether the model can REPAIR a stale page, an ingest-shaped task. Whether drift detection fires at all - that is atlas's canary fixtures, already working.

## What I could not establish
- ANY REAL PER-PAGE OR PER-TOKEN COST FOR INGEST. accreta-atlas/kb/knowledge/ is empty by design and sessions/ DOES NOT EXIST ON DISK, so there is no transcript anywhere in either repository from which to read actual usage. EVERY DOLLAR FIGURE I REPORT IS AN INPUT-SIDE ESTIMATE from bytes/4 (the bench harness's own estimator, which its comment says understates JSON) priced at verified rates. OUTPUT TOKENS - THE LARGER TERM FOR A WRITING TASK - ARE ENTIRELY UNMEASURED. Running one Sonnet arm would fix this in a few hours and SHOULD PRECEDE ANY OTHER COST CLAIM.
- WHETHER MODELS ACTUALLY FABRICATE LINE RANGES, AND AT WHAT RATE. F-ME-03 establishes that NOTHING WOULD CATCH IT. That is a statement about the CODE, not about model behaviour. The rate is exactly what the (a)/(b) script measures, and it does not exist yet.
- WHETHER A SMALL MODEL SUFFICES FOR DRIFT. Stated as a hypothesis throughout, deliberately. I found no measurement of it in either repository.
- ANYTHING ABOUT OPEN-WEIGHT MODELS. I ran none. Any figure would be a hosting provider's price for a model I have not tested on this task, failing both halves of the evidence bar.
- GENERALISATION BEYOND THIS CORPUS - AND I DECLINE TO ATTEMPT IT. n=1 on domain, and that domain is THE EASIEST AVAILABLE CASE: IETF RFCs are formally structured, stably numbered, written to be cited, with normative keywords defined by RFC 2119 and NATIVE cross-document contradictions (7231 vs 9110; 9110 vs 9111 on caching). A corpus of messy prose - meeting notes, internal wikis, mixed-quality PDFs - WILL SCORE WORSE ON EVERY METRIC HERE, particularly (c), where "the cited lines support the claim" is much harder to adjudicate when the source does not make discrete claims. Numbers from this experiment describe ACCRETA ON RFCs. They do not describe accreta on "any corpus", and reporting them as if they did would be the project's characteristic failure mode.
- THE ADRs IN SCOPE FOR OTHER REVIEWERS. I read the framing but did not evaluate ADR-0001's CIs, ADR-0004's conflicting figures, or the supersedes gap. The supersedes observation DOES touch my remit at one edge - the research preset makes supersession a first-class relation (rfc-http is built around 7231->9110) and nothing in the core interprets it, SO A MODEL ASKED TO RECORD SUPERSESSION IS WRITING INTO A FIELD WITH NO CONSUMER. I note it and leave the ADR judgement to whoever owns it.
